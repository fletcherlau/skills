# Markdown 文档结构审查

## 范围

对指定 Markdown 文档及其相关导航、引用做只读审查，报告可定位的结构问题与修改建议。
以通用 Markdown 的标题、列表、链接、图片和代码块为基础；元数据、表格、自定义锚点等扩展按仓库实际采用的语法判断。
内容事实核验、语言风格和站点构建属于其他审查范围。

## 输入

- 待审查的文档或变更范围，以及仓库根目录。
- 仓库现有的文档约定、目录结构和导航入口。
- 已有的 Diátaxis 分类结果（如有），用于判断目录归属。

## 审查步骤

1. **确定适用规则与范围**
   - 读取仓库文档约定、README 及相关配置，确认文档根目录、命名方式、必需元数据和导航方式。
   - 明确哪些是独立页面，哪些是被包含的片段、模板或自动生成内容，按各自用途审查。
   - 优先使用仓库已有的只读检查工具；查看配置与命令行为后再运行，并记录检查覆盖范围。
   - 没有明确约定的事项，区分可证实的问题与建议。明确检查对象与相关引用范围，避免无边界扫描全仓库。

2. **文件命名与标题结构**
   - 检查文件扩展名与内容格式是否匹配，命名是否符合仓库约定；尊重 `README.md` 等现有惯例。
   - 识别 ATX 标题（`#`）和 Setext 标题（下划线形式），排除代码块、注释和示例中的伪标题。
   - 检查标题能否表达章节关系，是否出现导致层级含混的跳级或重复。仓库要求单一一级标题时按约定检查；否则将标题组织问题作为建议，片段按嵌入位置判断。
   - 根据文档用途与已有模板检查章节顺序及必需章节。教程、操作指南、参考和解释文档可以采用不同结构。

3. **元数据与目录归属**
   - 仓库要求 YAML front matter 时，检查其位置、语法及约定的必需字段；未要求时，缺少 front matter 不构成问题。
   - 仓库采用 Diátaxis 分类目录时，用已有分类结果核对位置。没有分类结果时，从目录或元数据识别声明类别；证据不足时标为待确认。
   - 采用业务模块目录等其他组织方式的仓库，按其约定审查，不强制建立四类目录。

4. **导航与可发现性**
   - 找到仓库实际使用的入口，例如 README、目录索引页、手写链接清单或站点导航配置。
   - 检查需要供读者访问的新页面是否能从相关入口到达，移动或删除页面后入口是否同步更新。
   - 被包含的片段、模板、归档或明确不对读者展示的内容，按用途判断是否需要入口。
   - 若尚无导航约定，指出缺少阅读入口的具体影响并建议补充，不要求引入站点工具或专用目录语法。

5. **链接、图片与锚点**
   - 检查行内链接、引用式链接及其定义、图片路径；只把实际解析成链接的内容作为检查对象，排除代码示例。未定义的引用式标签若会显示为普通文本，指出可能漏写的链接定义及上下文依据。
   - 相对文件路径以当前文档所在目录解析，检查目标存在性和大小写；处理路径中的 URL 编码及片段后缀。
   - 站点根路径、无扩展名路由、重写路径和生成页面，根据已有配置解析。无法确定映射时标为未验证，不直接判为文件缺失。
   - 带 `#fragment` 的链接检查目标锚点。标题生成锚点、重复标题编号和显式锚点的规则取决于渲染器；有配置或现有检查器时使用其规则，否则标明待验证，避免猜测。
   - 普通页面链接和标题链接均可使用。发现标题变更导致失效时，建议修正引用；仅在已支持时建议稳定的显式锚点。
   - 对移动或删除的文档，在相关文档范围内查找旧路径的入站引用。
   - 外部链接的在线可达性按用户要求或仓库现有检查流程验证；未请求时不批量联网检测。认证、超时或访问限制单独记录，不据此断言链接失效。

6. **核对完成情况**
   - 对范围内的文件逐项记录：已检查、不适用或未验证及原因。
   - 将确凿的失效引用、无效的必需元数据及违反明确约定的事项列为问题；将缺少约定下的组织改进列为建议。
   - 只读审查期间保持被审文档、导航和配置不变。

## 输出

用简体中文报告：

- 审查范围与适用约定，包括用到的检查工具及其结果。
- 问题清单：文件与行号或章节、问题证据、违反的约定或对读者的影响、具体修改建议。
- 改进建议：与已确认问题分开列出；没有建议时省略。
- 未验证项：列出涉及的目标、原因及完成验证所需的条件。
- 完成状态：`结构审查完成：N 个问题，M 条建议，K 项未验证`。没有发现问题时，限定为“已检查范围内未发现结构问题”；保留未验证项，不将其计为通过。
