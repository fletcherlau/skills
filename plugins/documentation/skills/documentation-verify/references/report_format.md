# 文档核验报告格式

报告采用简体中文，先给出主要结论，再提供可复核的证据。
内容以已完成的核验为依据；证据冲突和证据不足单独呈现，不因无法定论而从报告中省略。

## 审查范围

说明本次检查了哪些文档或声明、目标版本与环境，以及实际使用的仓库和其他来源。
将文档范围与证据范围分开；没有检查的部分不包含在通过结论中。
共用来源可集中列出版本与状态，后续发现引用其编号。

## 结论分组

按验证流程中的分类组织实际存在的结果，省略空组：

- **文档不准确**：错误、已证实过时，或遗漏影响理解的适用条件。
- **实现与约定不一致**：已确认且适用的要求或契约与实现存在差异。
- **证据冲突**：相关来源相互矛盾，适用性或取舍仍需确认。
- **证据不足**：缺少足以判定声明的证据。
- **已证实**：可合并报告，注明声明性质与证据覆盖范围。

优先报告影响读者操作或理解的问题；是否阻断合入按项目已有规则决定。
明确标注且有依据的需求、历史和未来计划，可以作为相应性质的已证实声明，不要求已有实现。

## 单项发现

每项包含下列信息，可按复杂度合并简写：

```markdown
**声明**：文档位置及简短原文。
**性质与适用条件**：实现／运行／要求／历史／计划；目标版本、环境或时间范围。
**证据**：相关源码、契约、决策或观测的位置、版本与状态；说明实际支持或反驳了什么。
**结论**：分类及判断依据；证据只覆盖一部分时明确指出。
**建议**：与结论对应的最小后续动作；存在缺口时说明还需要什么证据。
```

源码证据包含仓库标识、提交或版本、文件与行号，必要时补充函数名或核验命令。
其他来源使用可定位的链接、章节、记录编号或观测入口，并注明相关日期与状态。
冲突项同时展示各方证据。记录“未取得”时说明影响，避免用缺失的证据支持否定结论。

## 建议如何随证据变化

- **当前行为描述有误**：在确认对应版本实现后，建议修改具体措辞、值或适用条件。
- **实现违反有效契约**：建议跟进实现偏差或由责任方确认契约变更，不能默认让文档改成当前错误行为。
- **版本或环境不同**：先明确文档适用范围，避免用开发分支覆盖已发布版本说明。
- **计划或历史表述**：有相应记录时保留其性质；把计划写成现有能力时建议澄清状态。没有计划依据时不自行改写成“未来将支持”。
- **来源冲突或不可得**：给出具体的补证或确认动作，不建议凭猜测删除声明。

以下为假设场景，展示结论边界：

| 文档声明与证据 | 结论及建议 |
| --- | --- |
| 文档说网关收到配置后才生效；配置生产端与另一仓库的网关加载路径共同支持该流程 | 已证实该版本的实现行为，列出两仓库证据；不外推为某个环境已生效 |
| 契约已确认成功响应应为 201，文档与契约一致，但对应版本实现返回 200 | 文档准确表达约定；实现与约定不一致，跟进实现或契约裁定 |
| 文档说生产已启用某功能，只找到支持该功能的源码，未取得生产版本与生效配置 | 证据不足，补充部署及运行证据 |
| 文档标明某功能是未来计划，且有效的计划记录支持该表述，尚未实现 | 已证实计划状态，无需因缺少代码修改文档 |
| 当前仓库没有找到重试逻辑，调用关系指向尚不可访问的外部组件 | 证据不足，补充对应组件及版本；不能判定重试能力不存在 |

## 完成说明

说明已核验范围、确定的问题和仍需补证的事项。
没有发现不一致时写“已核验范围内未发现不一致”，并保留未覆盖或证据不足的说明。
省略中间假设与搜索过程的流水账，保留复核结论所需的证据和简明理由。
