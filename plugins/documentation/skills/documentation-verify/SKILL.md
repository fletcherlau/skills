# 文档准确性核验

## 范围

根据文档声明的性质、适用版本和环境选择证据，核验其准确性。
源码是实现行为的重要依据；需求与契约、设计决策、计划记录和运行状态分别回答不同的问题。
证据冲突时报告差异，不预设文档或实现哪一方必然错误。

核验范围由声明决定，可以涉及一个或多个仓库，也可以涉及仓库外的相关证据。
当前仓库是可能的入口，不代表完整的实现边界；不预设仓库数量、元仓库或目录布局。
文档审查范围与证据范围分开确定：核验一篇文档可能需要多个仓库，但不因此扩大到这些仓库的全部文档。

## 输入

- 用户指定的文档、变更范围或待核验声明；未指定时从相关 `git diff` 识别范围。没有可用范围时先澄清，不把整套文档默认视为变更。
- 可访问的项目说明、源码、测试、配置、接口定义及相关证据。
- 文档适用的版本、环境或时间范围，以及已有需求、契约、设计或计划记录（按声明需要使用）。

## 流程

### 1. 识别声明与证据范围

1. 提取可核验声明及文档位置，区分当前实现、运行现状、预期要求、历史理由和未来计划；必要时拆开混合声明。
2. 从用户上下文、项目说明、依赖和代码引用中定位相关实现与证据，不按当前 Git 仓库的边界截断追踪。
3. 记录版本、环境和时间等适用条件。条件缺失或含糊时，限定可核验范围或提出待确认项。

定位仓库、选择证据及逐类核验时，读取 [验证流程](references/verification_procedures.md)。

### 2. 核验与定性

1. 按声明类型核对适用证据；实现类声明结合源码搜索、入口追踪、测试或 schema 等不同核验路径交叉检查。
2. 为证据记录可追溯位置及适用条件。跨仓库或跨来源的结论，说明证据之间的关联及尚未核实的环节。
3. 完成必要核验后定性：已证实、文档不准确、实现与约定不一致、证据冲突或证据不足。分类标准见验证流程。
4. “搜索未找到”只说明当前搜索结果；缺少相关仓库、访问权限或运行证据时保留缺口，不据此判定功能不存在。
5. 文档明确描述需求、历史或计划时，按其自身性质核验；与当前实现不同不自动构成文档错误。

### 3. 输出结论

1. 按 [报告格式](references/report_format.md) 汇总已核验结论、冲突和未能核验的事项。
2. 建议由证据决定：可以是修改文档、跟进实现偏差、补充适用条件，或进一步取得证据。
3. 报告实际覆盖范围；只核验了部分声明时，不宣称整篇文档或整个系统均已验证。

## 执行边界

- 核验默认只读；修订文档、修复代码或改变环境需要属于用户已授权的任务。
- 执行示例前确认其副作用和适用环境，优先使用现有测试与可安全复现的验证路径。
- 依据证据给出结论，区分查到测试文件、实际测试结果、配置发布与运行生效。
- 遇到决定结论的证据缺口时记录缺口并继续可独立核验的部分；必要时请求缺失的仓库、版本或来源信息。
- 最终报告包含结论、证据与判断依据，省略中间猜测；证据不足也必须明确呈现。
