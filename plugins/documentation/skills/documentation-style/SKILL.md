# Markdown 文档风格审查

## 范围

只读审查指定文档的表达与排版，提供有规则依据的局部修改建议。
以通用 Markdown 为基础，扩展语法根据项目配置与约定判断；不因文件扩展名为 `.md` 就推定其使用某种扩展方言。
文档分类、标题层级、导航与链接完整性、事实准确性分别交给对应审查，避免在风格报告中重复定性。

## 输入

- 待审查的文档或变更范围、目标读者与文档用途。
- 用户指定或项目现有的写作规范、术语表、格式检查配置（如有）。
- 随附的 [通用 Markdown 写作指南](references/doc-style-guide.md)。

## 流程

### 1. 确定范围与适用规则

- 明确本次是全文审查还是变更审查。变更审查先读取改动涉及的完整句子、前后段落、相关术语定义与章节，依据上下文判断指代、重复和表达是否有问题。
- 变更审查重点报告此次新增或加重的问题；把对照前后的依据写清楚。未修改的上下文用于理解，不因此扩大到整篇文档的润色。历史问题若阻碍本次判断，单独说明影响并区分于本次发现。
- 读取随附指南和与本次范围相关的项目规范，记录来源、适用文件与语言。
- 按用户明确要求、项目明确规范、随附指南的顺序确定规则；高优先级规则覆盖相冲突的低优先级规则。现有文档的惯用写法可辅助判断一致性，不能单独当作强制规定。
- 英文拼写地区、标题大小写、标点、换行和格式偏好按语言与项目约定采用。没有约定时，将指南中的建议作为建议，不升级为强制违规。
- 同层级规范存在冲突时，先核实适用范围和状态；仍无法裁定的事项单独列出，继续其他检查。
- 默认使用已取得的指南；只有项目明确采用且本次需要时，才读取外部规范或扩展语法资料，不默认获取特定框架的语法手册。
- 指南无法访问时继续依据其他可用规则审查，注明缺失来源与受影响的范围；没有可用依据的项目标为未审查，不凭空生成规则。

### 2. 审查表达与排版

- 根据指南中表达、术语、语言、标题、列表、代码示例和链接文字的规则，逐项检查适用部分。
- 检查正文中可确认的错别字、漏字、意外重复和语法问题，引用指南的“基础语言正确性”规则说明具体错误；这些检查不以项目另行制定语言规范为前提。
- 按段落实际语言应用规则；区分正文、代码、标识符、命令输出和原文引用，保留需要逐字准确的内容。
- 判断问题对理解、操作或一致性的实际影响。通用 Markdown 中等价有效的写法，仅在违反明确约定或造成具体问题时报告。
- 遇到扩展语法时核对项目支持情况；支持情况未知时标为待确认，不直接认定为错误。
- 命令、示例和描述疑似涉及事实错误时，记录位置并交给准确性核验；风格修改不改变技术含义，也不为检查排版执行示例命令。

### 3. 为每条发现提供依据

- 给出文档文件与行号或段落、简短原文、规则来源与章节或行号，并引用支持判断的具体规则短句。
- 明确规则为何适用于此处、读者会受到什么影响，以及最小修改建议。
- **语言错误**：结合上下文可确认的文字或语法错误；技术术语、合法语言变体和刻意引用不按普通拼写处理，拿不准时说明疑点而不直接判错。
- **规范违规**：违反已确认且适用的强制规则，有可以复核的文本证据。
- **改进建议**：依据指南中的建议或可读性原则，说明具体收益；主观偏好不能伪装为规则要求。
- 按读者影响排序：先处理会造成误解或妨碍操作的问题，再处理术语和表达一致性，最后是局部排版。分类仅说明发现性质，不代表优先级；依据上下文说明影响，不夸大风险。
- 无法找到适用规则时，不把个人写法偏好列为风格问题；需要确认的规范或语法边界放入未审查／待确认项。

### 4. 核对覆盖范围

确认指定文档已按适用规则检查；未访问的指南、不适用的语言规则、未确认的扩展支持和未完成部分分别记录。
多个实例违反同一规则时可合并报告，但保留可定位的受影响位置。
保持被审文档不变；用户要求修订时再按已授权范围修改。

## 输出

用简体中文给出适用规则与审查范围，再按读者影响排序列出发现，并标注语言错误、规范违规或改进建议；未审查／待确认事项另列，没有时省略。
每条发现包含：文档位置与原文、分类、规则来源与引用、适用性与影响、具体修改建议。变更审查需说明问题与本次改动的关系。
完成状态使用 `风格审查完成：N 项语言错误，M 项规范违规，K 条改进建议，U 项未审查／待确认`。
没有发现问题时限定为“已审查范围内未发现风格问题”；缺失的规则或未完成的检查不计为通过。
