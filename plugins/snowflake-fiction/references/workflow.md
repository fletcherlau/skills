# 共同工作协议

每个技能开始工作时读取本文件。它定义本包的状态与协作约定，不增加雪花方法的步骤。

## 作者选择与写入

- 保留作者已给出的题材、语言、文风、视角、受众、结构及禁区。未知偏好可不填写；提供方案时标为候选，不暗中选定。作者可授权 Codex 代选，记录授权范围。
- 创作建议和既定事实分开；歧义或冲突不能靠编造事实消除。先查材料能回答的事实，再把作者选择留给作者。按依赖顺序只问当前工作所需的关键问题；下游问题留到前提决定后，允许以明确的暂定版本推进。
- 新项目建议目录 `novel/<作者指定项目名>/`，先确定位置；已有项目保留其文件组织，不强迁目录。当前请求未授权保存时先在对话交付可复制产物与状态，不声称已写文件。不能改动插件源文件来记录小说。
- 保存前读已有文件；不覆盖作者原稿。修订采用新版本文件或作者授权的明确位置修改，保留可恢复旧稿。一次只处理已请求的范围，不自动发布、分享或生成整本小说。

## 状态与恢复

使用导航技能的 [项目状态模板](../skills/snowflake-navigator/assets/project-state.md)，保存为项目内 `snowflake-state.md` 或作者已有状态文件。简单任务也只记最小必要字段，无需一次填完所有设计。

每项阶段/人物/场景分别记录：状态、覆盖范围、产物路径及版本、依据路径/定位及版本、是否作者确认、未决项和下次入口。

状态含义：`missing` 无材料；`draft` 工作草案；`ready` 达到当前范围完成条件且作者已接受或明确授权代选；`stale` 依据变化待复核；`skipped` 作者选择跳过并有理由。`ready` 可用于局部项，整体阶段仍需写清未覆盖范围。不能把未回答、沉默或过去的确认当成新版本的认可。

没有文件工具时在对话输出同样状态，明确请在下次带入。新会话先读状态，再读本次范围的实际产物和相邻正文；核对版本、路径、缺页和已有手工修改。状态与文件冲突时以实际证据列出差异，请作者选择权威版本，不根据时间戳独断。若发现未记录的手工修改，先做影响分析再继续。输入太大则分批读取，保存已读范围与未读部分的定位，不据摘要臆测全文。

接入旧大纲/稿件：保留原材料为事实来源，建立产物索引；区分直接摘录事实、推断、候选及未知。可直接在所需中间阶段工作；仅补本次任务缺口。建立摘要不意味着重写正文或补齐前面所有文档。

## 版本、回退与一致性

1. 说明发现的新信息、所在文件/场景与当前依据的冲突；区分创作选择和连续性错误。
2. 给出可选修订：保持原事实并改当前场景，或由作者决定改变事实并回退相关设计。已明确授权的范围内可直接修订，其余重要作品决定交作者选择。
3. 接受变更后记录旧值、新值、理由、作者决定和版本。只对有依赖的产物/人物/场景标 `stale`，沿实际依据关系传播；不是把所有更高编号都作废。旧稿保留、链接更新，不自动重写受影响全文。
4. 复核受影响项，说明通过/仍冲突/暂缓及证据，更新其依据版本。未解决冲突继续保持 `stale`；跳过项无需造出产物，但其接入说明有变时也要复核。

检查按当前产物范围进行：

| 关系 | 具体检查 |
| --- | --- |
| 核心 → 梗概 → 场景 → 正文 | 主角与故事承诺是否保持，结局是否回应，关键事件是否有覆盖 |
| 人物摘要 → 人物视角 → 档案 → 行为 | 目标与选择是否相容，人物变化是否有过程，关系与能力是否一致 |
| 时间 / 地点 / 视角知识 | 行程、年龄和先后是否可能；人物何时获得信息，叙述者知道什么 |
| 铺垫 → 揭示 / 回收 | 新场景是否提前泄露，重排是否破坏伏笔，支线是否仍有收束 |

检查报告写“依据/定位—冲突或通过—影响范围—处理决定”，不能只写“已一致”。全书一致性只在实际检查全书范围后声明。

## 每次结束

交付本次产物、已完成范围、待作者决定/待补信息、一致性结果及下一入口。状态保存后注明真实路径；正文记录实际出口状态、已写/待写场景和续写起点。整个十步服务初稿，后续精修可返回这些产物，不能把初稿完成称为已出版质量。
