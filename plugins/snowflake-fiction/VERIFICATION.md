# 验证记录

## 范围与命令

本包验证分为结构检查、情景演练与两轴审查。不将任一检查称为桌面端插件安装或小说创作质量验证。

```sh
python3 plugins/snowflake-fiction/scripts/validate_package.py
python3 plugins/snowflake-fiction/scripts/test_validate_package.py
```

全部 11 个技能另用官方 skill-creator 的 `quick_validate.py` 检查 YAML 与命名；该工具位于编写环境，不作为本包依赖。包校验器仅解析本包所用的简单标量 YAML，属于可分发的结构检查。

## 情景验收

| 情景 | 应观察到的结果 |
| --- | --- |
| 没有文件，只说想写小说 | 不虚构题材或文风，询问/整理当前最小灵感；说明状态未保存 |
| 只有一句“有人找东西”，要求第 2 步 | 聚焦主角、目标或结局的必要缺口，候选保持未确认 |
| 有四章稿件而无状态 | 保留原稿，记录已读范围，提取场景/人物事实后按任务接入，允许中途继续 |
| 反派视角重述已有故事 | 先读取并推荐第 5 步，不以第 3 步摘要或第 7 步档案替代 |
| 明确跳过第 9 步 | 读第 9/10 步，记录 skipped 与替代输入，仍能写当前场景 |
| 正文请求“继续” | 核对状态、尾段及场景 ID，只写下一场景，整体第 10 步仍可为 draft |
| 角色原来知道秘密，现在决定不知道 | 原事实与候选分开，列依赖并保留旧版本，仅相关项 stale，复核后清除 |
| 主角确认只处理人物 C002 | 局部完成不冒充全部人物或全部阶段 ready |
| 状态声称已完成但文件有手工修改 | 核对实际文件、列权威版本冲突与影响，不凭时间戳强行覆盖 |

两轴审查依照实际读取的 Matt Pocock `code-review`：规范轴对 Codex/仓库格式与可维护性，需求轴对本次用户要求。

## 实际结果（2026-10-08）

- 全部 11 个技能通过官方 `quick_validate.py`；全部 11 份 UI 元数据通过 PyYAML 解析。最长 `plugin:skill` 为 49/64 字符，所有模板/共享链接在整包内可解析，marketplace 从仓库根正确解析。
- 包校验器 8 项测试通过：正常整包、缺步骤、断共享引用、未闭合 frontmatter、空正文、越界引用、错误市场根路径、组合标识超限。测试只修改临时副本。
- 独立 Standards 审查发现未闭合 frontmatter 可误通过；修复结束边界与非空正文检查，增加两项失效测试，审查者复核通过。没有剩余规范发现。
- 独立 Spec 审查读取全部 11 个技能与共享资料，未发现阻塞性需求偏离。实生成导航/恢复状态、约 200 字的 S003 正文及 C002 反派完整视角梗概：第 9 步 skipped、S004 未写、整体仍 draft、未知信件内容未被确认为事实。
- 其他情景为短模型回应：输入不足、四章稿件的局部读取、局部完成、状态/手工修改冲突及按依赖传播 stale。它们不是自动化断言。事实变更只将相关人物线→转折→场景→正文列为 stale，保留兼容或无依赖项。
- 可复读的虚构输入与实际输出见 [短试用证据](examples/behavior-smoke.md)。原稿未改，未在本包存入小说项目状态。新增文件差异空白检查通过；原 checkout 仍在 documentation 分支，未跟踪 `.serena/` 保留。

规格与规范审查是两个独立 agent 执行；试用是 Spec 审查中的按指令演练，没有借此声称已验证客户端安装或自动发现。

## 未验证边界

未进行桌面插件安装、技能选择器自动发现、长篇跨会话实测或真实作者满意度验证。原方法建议的页数/时长不是本包完成门槛。未合并、部署或发布插件目录。
